# 项目排查与升级方案 · 2026-11-02

当前阶段：基础监控功能和多主题界面已经成形，正在补齐设备设置与新固件报文兼容；尚未达到多 AMS、AMS HT、多机型均经过验证的完成状态。

本次检查包含 HEAD `c9cdd59` 和工作区未提交改动。只新增本报告，未修改固件业务代码、提交或烧录。用户提到的“amht”在此按 AMS HT 理解。

## 1. 已经完成到哪一步

- WiFi + MQTT-TLS 局域网连接、订阅 report、手动请求 pushall。
- 打印进度、层数、剩余时间、状态、喷嘴和热床温度；腔温支持旧字段及 `device.ctc.info.temp` 路径。
- 12 套主题、运行时中英文选择；部分主题支持组件排序。
- 一个四槽 AMS 与一个外置料盘的基础展示。
- 热点配网、WiFi 扫描、保存前验证 WiFi 和 MQTT 连接、NVS 配置保存。
- 设备端设置：亮度、自动熄屏、进入重新配网、返回；按键唤醒。
- 工作区新增了 MQTT 分片重组、按字段扫描解析与串口截屏工具，尚未提交。

不能据此宣称完成的部分：多 AMS / HT、机型能力识别、双喷嘴/多个外置料盘、各机型真实报文回归、所有主题和语言的实机验收、统一的设置页视觉。

## 2. 已确认的问题

### A. 新增 AMS / HT 被截断，根因涉及数据模型、解析器和界面

优先级：P1，核心功能缺口。

- `main/bambu_state.h:28-29` 固定 `BAMBU_AMS_COUNT = 1`、每台 4 槽。
- `main/bambu_mqtt.c:360-381` 按数组顺序写入，达到 4 槽便停止；没有保存 AMS 单元的 ID、类型或温湿度等信息。
- 12 个 `style_*.c` 均采用四槽加一个外置槽；页数为固定值或编译期决定。
- `ams_count` 实际存的是已解析的料槽数，命名容易使后续代码误认为是 AMS 设备数量。

复现：向当前解析函数输入“四槽 AMS + 一个单槽设备”的合成报文，最终只有 4 槽，新增设备被丢弃。

结论：仅增加页面或修改 `BAMBU_AMS_COUNT` 不能完成适配。

### B. 当前料槽身份和高亮逻辑不能扩展到多设备

优先级：P1。

- `parse_tray_obj()` 只拿槽内 `id` 与 `tray_now` 比较，丢失所在 AMS 的 ID。
- 多个主题用 `active_tray >= 4` 判断外置槽；新增设备编号也会落入这个分支。
- 仅 `tray_now` 更新时，已有料槽的 `active` 不重新计算。

主机复现：单元 ID 为 1、当前编号为 4、槽内 ID 为 0 时，该槽未高亮；从槽 0 切至槽 1 的增量消息后，槽 0 的 `active` 仍为真。

后续应统一表达设备身份与槽身份，并按实际协议版本解释活动来源；HT、普通 AMS、外置槽不能共用一个大小比较规则。

### C. 仓库样例中的风扇读数被解析为 0

优先级：P0，已有读数错误，建议首先修复。

- 样例 `docs/Topic-device.json` 的三个风扇字段均为字符串，例如 `"2"`、`"10"`。
- 当前 `json_int()` 仅接受 JSON 数字的起始字符，字符串返回 0。
- 直接编译当前解析函数并输入仓库样例，三个风扇输出均为 0。
- Gauge 页面又把这些原始值直接加上 `%`；即便修复类型，也仍需核对协议量程和风扇语义。

官方 BambuStudio 的旧协议解析会读取字符串并转换量程，同时有 `fan_gear` 和新协议路径，不能假设所有机型都直接返回 0–100 百分比。

### D. 增量报文合并及有效数据判断有缺口

优先级：P0/P1。

- `vt_tray` 解析嵌在 `if (print.ams)` 内；仅更新外置料盘的增量消息被忽略。主机复现外置 TPU 没有写入状态。
- 每个收到的料槽先 `memset`，再按数组位置重写；若固件发送部分槽/部分属性更新，旧属性会丢失或槽位错位。这一风险尚需对应机型的真实增量报文确认。
- 只要进入 `parse_print_json()` 就更新 `last_update_ms` 和 `data_valid`，没有要求成功提取监控字段。
- 主机复现：非对象值 `42` 也被标记为有效数据。该用例验证缺少对象类型校验，并非声称打印机会发送此报文。
- 全局状态由 MQTT 写、UI 读，未见快照或互斥保护；建议在重构状态层时一并处理，避免读到混合更新。

### E. 无数据、不支持、断线与真实 0 尚未区分

优先级：P1。

- 状态初始化为 0 和 IDLE，没有每字段有效性/支持能力标记。
- 多个主题直接显示温度 0、层数 0/0；例如 Gauge 腔温直接显示数值，并非所有主题都显示 `--`。
- `last_update_ms` 目前只有写入，未见 UI 使用它判断数据是否过期；断线后旧读数仍保留。
- MQTT 建连即被当作连接成功，尚未区分“已订阅”“已收到有效首包”“数据过期”。

建议：保留增量合并能力，同时增加连接阶段、字段有效性和数据时效；不支持或未获取显示 `--`，过期数据明确提示。

### F. “口口”仍有可定位的字形缺失

优先级：P1。

- 当前中英文表中实际中文用字，在 14px / 20px 两份字库内均有覆盖。
- 但 `main/ui/ui_settings.c:182` 的硬编码底栏“确认 / 选择 / 调整”中，**“调”“整”两字均不在这两份字库内**。
- 字体生成只采集词库与 `ui_lang.c`，无法自动纳入设置页散落的中文文案。
- 旧校验脚本 `tools/check_cjk_coverage.ps1` 仍在 `ui_lang.h` 查找已移除的 `#if CFG_LANG == LANG_CN`，实际运行失败，不能承担当前回归检查。
- 设置页底栏硬编码中文，因此英文模式也会出现中文；重置确认等长文案未设置明确的文字列宽，需要视觉验收。

处理方向：先统一文案入口、修复字形校验，再检查每个标签实际使用的字体。字形缺失、错误字体、翻译语义和文本裁切分别验证。

### G. 设置页只复用了色板，没有完整延续主题风格

优先级：P1。

- 全屏覆盖层采用固定四卡片布局，独立创建标题和底栏。
- `ui_settings.c:157` 将主题的 0 圆角强制改为 10；像素、SSD、工业类界面的直角语言无法保留。
- 卡片没有显式清空 LVGL 默认 padding，精确摆放和中英文长文案存在裁切风险。
- 选中边框由 1px 变为 2px，会改变内容区域；编辑状态使用 accent 文字，还需检查浅色/高亮主题的对比度。

处理方向：共用设置逻辑，提供主题化的页头、页脚、行、选中态、分隔线和装饰；避免复制 12 份设置业务代码。

另有一个设置交互问题：长按退出编辑后，亮度预览没有立即回退到保存值；保存操作也忽略 NVS 写入错误，可能让用户误认为已成功保存。

### H. 目前无法证明“每个型号的信息都拿到了”

优先级：P1，验收缺口。

- 状态结构只有一组喷嘴温度和一个外置槽，没有机型/固件/能力模型。
- 样例已有 AMS 温湿度、干燥时间、HMS、打印错误、新设备结构等内容，当前只消费其中部分基础字段。
- 仓库只找到一份 report 样例，未发现项目自有的解析回归测试或模拟器。
- 配网阶段只验证 MQTT CONNECTED，不订阅 report；因此不能验证序列号对应的 topic 能否收到数据。

应改为明确的支持清单：哪些字段是基础功能、哪些是机型扩展；每个组合标注“源码已适配 / 样例已通过 / 实机已验证”。不以单纯收到报文作为全部字段正确的证明。

### I. 文档与构建交付存在漂移

优先级：P2。

- README 仍写“长按确认重新配网”，代码已改为末页向下进入设置，再选择重置网络。
- README 的 ESP-IDF 版本与本地构建脚本版本不同。
- `build/` 的应用 bin 为 11 月 1 日，full/merged 固件为 9 月旧产物；旧合并包不能代表当前应用代码。

建议每次发布统一生成应用包/全量包、版本及提交标识，记录是否包含未提交变更，并同步按键说明。

### 第二批：完成多设备耗材与动态分页

- [ ] 数据层保存 AMS 单元 ID、类型、槽列表、在线/有效状态和温湿度、干燥状态等可用信息。
- [ ] 区分 AMS / AMS Lite / AMS 2 Pro / AMS HT / 外置槽；能力未知时保守展示实际收到的字段。
- [ ] 活动耗材统一解析为设备与槽身份，支持无活动料槽和协议特殊值。
- [ ] 增加统一页面目录，按已发现硬件生成页数，不再让 12 套主题分别决定拓扑。
- [ ] 资源受限时设明确设备上限，超限提示，不能静默丢弃。

建议页面顺序：**监控总览 → AMS A → AMS B（有则显示）→ AMS HT（有则显示）→ 外置耗材（按能力/数据）→ 设置**。

AMS HT 应有独立页面，显示单槽耗材；温度、湿度、干燥状态/剩余时间仅在收到有效字段后展示。官方 BambuStudio 也区分四槽 AMS 与单槽 HT，并按类型计算身份，不能一律当作额外四槽。

内存方案：保留现有常驻对象/瞬时切换的思路；复用一个耗材页组件并绑定当前设备，避免给每台 AMS 创建整套隐藏 LVGL 对象。拓扑变化时更新页面目录，并把当前页约束到有效范围。

验收组合：无 AMS、一个 AMS、一个 HT、AMS + HT、多个 AMS、设备拔除/重新连接、设备数组顺序改变、非连续 ID、活动料源切换；页码和设置入口始终正确。

### 第三批：统一设置页与交互

- [ ] 设置项和编辑状态保持一套逻辑，主题通过共享组件/绘制接口表达样式。
- [ ] 延续各主题的标题栏、底栏、圆角/直角、间距、选中态和装饰。
- [ ] 统一文字列宽和长文案策略；对英文标签和二次确认态单独验收。
- [ ] 固定边框几何；选中/编辑/危险动作的反馈不依赖低对比度文字。
- [ ] 取消亮度编辑立即恢复保存值；保存失败显示反馈，保存成功后才确认结果。
- [ ] 主题和语言可考虑直接在设备设置里修改，减少只改显示偏好也要重新配网的操作。

验收：12 主题 × 2 语言，检查正常、选中、编辑、重置确认及退出状态；截图覆盖全部页面，关键布局再用实机按键操作确认。

### 第四批：建立机型能力和发布验收

- [ ] 按机型、固件版本、AMS 组合收集脱敏的全量与增量真实 report。
- [ ] 建立字段清单：JSON 路径、类型、单位、转换、适用能力、缺失语义、验证状态。
- [ ] 对 X1/P1/A1 与代码提及的新结构机型分别验收；双喷嘴等扩展需要独立建模。
- [ ] 覆盖待机、准备、打印、暂停、完成、错误、断网及恢复；优先补 HMS/错误信息页。
- [ ] 对大 report 分片、JSON 转义、异常输入、内存分配失败做回归，记录最小空闲堆和最大连续空闲块。
- [ ] 统一发布脚本、合并固件、按键文档和支持清单。

当前重组缓冲按 2 次幂增长，虽然声明上限 96 KiB，实际扩容到 128 KiB 会被拒绝，所以最多分配 64 KiB。大包边界与内存不足的日志应区分；本次未证明实机会发生内存耗尽。

## 4. 本次验证及边界

- 静态检查状态模型、MQTT 解析/连接、12 套主题、设置页、双语表、字体生成和配置保存。
- 使用 MinGW GCC 直接编译当前源文件中的解析函数和项目使用的 cJSON，通过主机探针复现：风扇字符串归零、多设备截断、非零单元活动槽不匹配、外置槽独立增量丢失、活动状态不刷新、非对象也标记有效。
- 另复现普通不透明黑色 `000000FF` 被判断为透明，因为透明判定只比较前六位。该项应纳入耗材颜色回归。
- 对两份字库 cmap 做静态检查：语言表中文覆盖完整，设置底栏“调整”缺失；旧 PowerShell 字体校验脚本运行失败。
- 查看仓库现有 11 月 1 日截图，仅能证明该时刻页面的外观；其中零读数不能用于断定当前打印机状态，也不代表全部主题已验收。
- `idf.py build` 入口在本环境因 `Windows-` 平台识别报错退出；直接运行现有构建目录的 `ninja -C build` 成功。此次属于增量构建检查，没有重新编译源文件；应用分区剩余约 44%，这不等于运行时 RAM 充足，也不是干净构建验收。
- 未连接真实打印机、读取设备当前串口、烧录或验证真实 HT 报文。HT 特殊字段与各机型支持结论仍需真实数据和实机补齐。
