# 第一、第二批实施记录 · 2026-11-02

对应 [项目排查与升级方案](project-audit-2026-11-02.md)。本次完成代码实现、主机回归、LVGL 界面运行测试与固件编译；没有烧录或进行真实打印机验收。原工作区未提交的 MQTT 分片接收和截屏工具改动继续保留。

## 数据读取

- 将 report 解析独立为 `main/bambu_report.c`，保持低内存策略：完整扫描校验 JSON，但只为字符串、单槽等小片段构建 cJSON 对象。
- 数值支持 JSON 数字和数字字符串，检查类型、范围及完整数值；拒绝非法 JSON、非对象 print 和没有已支持有效字段的消息。
- 风扇优先读取 `fan_gear`，否则按官方旧协议量程转换三个速度字段；Gauge 腔体风扇改为 `big_fan2`，`big_fan1` 是辅助风扇。
- 温度、进度等增加有效性标记；无效值显示 `--`，不把缺失字段当作实际 0。
- 外置料盘不再依赖同一消息是否含 AMS；按 AMS ID、槽 ID 合并增量，保留未更新属性；活动槽每次重新计算。
- 黑色 `000000FF` 与透明色 `00000000` 分开处理，保留完整 RGBA 字符串；余量未知值 `-1` 显示 `--`。
- 依据明确的设备/槽存在位图清理拔除设备和空槽；位图字符串按官方实现读取为十六进制，优先采用可用的 `ams_exist_bits_raw`。
- MQTT 写入和 UI 读取通过临界区发布/复制快照；新连接清空旧状态，等待有效首包。空闲 30 秒无报文时限频请求全量，避免空闲打印机因不主动推送而持续过期；断线、等待首包、超过 60 秒没有有效数据均有明确界面状态。
- 分片接收补充总长度、偏移和剩余空间检查；断线清空分片状态；96 KiB 上限不再因 2 次幂扩容而实际缩成 64 KiB。申请失败日志与容量上限一同显示。

## 多设备与页面

- 最多存储 12 个 AMS 单元，每单元最多 4 槽；这是本固件的存储上限，不是对所有打印机可连接数量的承诺。超限显示提示。
- 保存设备 ID、类型、槽列表、温度、实际湿度或湿度等级、干燥状态和剩余时间。
- 普通 AMS / Lite / 2 Pro 沿用各主题已有四槽页面；HT 使用独立单槽页，展示可用的温湿度和干燥状态；外置耗材独立一页。
- 页面目录由发现的设备生成：总览 → 各 AMS / HT → 已上报的外置耗材。设置入口位于最后一页之后。
- 设备按 ID 排序，当前选择绑定设备身份；新增较小 ID 的设备不会导致跳到另一台，当前设备拔除时返回总览。
- 所有设备共享原主题的四槽视图与一套单槽视图，切页更新绑定数据，不按设备数量成倍创建 LVGL 对象。
- 现有四槽页的外置耗材快捷行保留，因此有外置耗材时也能在该页查看；独立外置页提供更清楚的单槽读数。
